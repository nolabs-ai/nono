## Homebrew (macOS/Linux)

```bash
brew install nono
nono --version
```

## Linux Package Managers

### Debian/Ubuntu

Download the `.deb` package from [GitHub Releases](https://github.com/nolabs-ai/nono/releases):

```bash
VERSION=$(curl -sIL https://github.com/nolabs-ai/nono/releases/latest | grep -i location | grep -oP 'v\K[0-9a-zA-Z.-]+')
ARCH=$(dpkg --print-architecture)
wget https://github.com/nolabs-ai/nono/releases/download/v${VERSION}/nono-cli_${VERSION}_${ARCH}.deb
sudo dpkg -i nono-cli_${VERSION}_${ARCH}.deb
nono --version
```

### Fedora (COPR)

nono is available from the official [COPR repository](https://copr.fedorainfracloud.org/coprs/always-further/nono/):

```bash
sudo dnf install 'dnf-command(copr)'
sudo dnf copr enable always-further/nono
sudo dnf install nono-cli
nono --version
```

<Note>
  If your Fedora version isn't available in COPR, use the manual RPM install below.
</Note>

### Manual RPM (RHEL/openSUSE and fallback)

Download the `.rpm` package from [GitHub Releases](https://github.com/nolabs-ai/nono/releases):

```bash
VERSION=$(curl -sIL https://github.com/nolabs-ai/nono/releases/latest | grep -i location | grep -oP 'v\K[0-9a-zA-Z.-]+')
ARCH=$(uname -m)
wget https://github.com/nolabs-ai/nono/releases/download/v${VERSION}/nono-cli-${VERSION}-1.${ARCH}.rpm
sudo dnf install ./nono-cli-${VERSION}-1.${ARCH}.rpm
nono --version
```

For openSUSE, use `sudo zypper install ./nono-cli-${VERSION}-1.${ARCH}.rpm` instead.

### Nix

nono is available in [nixpkgs](https://search.nixos.org/packages?channel=unstable&show=nono) as `nono`:

```nix
# Installing in NixOS
environment.systemPackages = [
  pkgs.nono
];
```

```bash
# Loading in shell
nix shell nixpkgs#nono
# Or using the legacy CLI
nix-shell -p nono
```

### Arch Linux (AUR)

nono is available on the [Arch User Repository](https://aur.archlinux.org/packages/nono-ai-bin) as `nono-ai-bin`, an officially maintained binary package that tracks official GitHub releases and verifies SHA256 checksums. It supports `x86_64` and `aarch64`.

```bash
# Using yay
yay -S nono-ai-bin

# Using paru
paru -S nono-ai-bin

# Manual install with makepkg
git clone https://aur.archlinux.org/nono-ai-bin.git
cd nono-ai-bin
makepkg -si
```

Other distributions are in the process of being packaged. In the meantime, you can use the prebuilt binaries or build from source.

## OCI Registry (GHCR)

nono binaries are published as OCI artifacts to the GitHub Container Registry, making them consumable with [`oras`](https://oras.land) in CI pipelines and air-gapped environments without custom scripting.

```bash
# Pull the binary for your platform (auto-resolves to the right tarball)
oras pull --platform linux/amd64 ghcr.io/nolabs-ai/nono:latest-binary -o .
tar xzf nono-*.tar.gz
sudo mv nono /usr/local/bin/
nono --version
```

Replace `linux/amd64` with your platform. Supported values: `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`.

### Verify the signature

Each release is signed with [Cosign](https://docs.sigstore.dev/cosign/overview/) keyless signatures (Sigstore). To verify before installing:

```bash
TAG=v0.81.0          # git release tag (with "v")
VERSION="${TAG#v}"   # OCI tags omit the "v"
cosign verify \
  --certificate-identity "https://github.com/nolabs-ai/nono/.github/workflows/release.yml@refs/tags/${TAG}" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "ghcr.io/nolabs-ai/nono@$(oras resolve ghcr.io/nolabs-ai/nono:${VERSION}-binary)"
```

### Pin to a specific version

```bash
oras pull --platform linux/amd64 ghcr.io/nolabs-ai/nono:0.81.0-binary -o .
```

## Platform Support

| Platform | Mechanism | Status |
|----------|-----------|--------|
| Linux (kernel 5.13+) | Landlock LSM | Supported |
| macOS | Seatbelt (sandbox_init) | Supported |
| Windows (WSL2) | Landlock LSM (via WSL2 kernel) | Supported ([84% feature coverage](/cli/internals/wsl2-feature-matrix)) |
| Windows (native) | - | Not supported |

### WSL2

nono runs inside [WSL2](https://learn.microsoft.com/en-us/windows/wsl/) using the same Landlock enforcement as native Linux. The WSL2 kernel (6.6) ships with `CONFIG_SECURITY_LANDLOCK=y` enabled by default. Install nono inside your WSL2 distribution using any of the Linux methods above.

See [WSL2 Support](/cli/internals/wsl2) for the full compatibility details and known limitations.
